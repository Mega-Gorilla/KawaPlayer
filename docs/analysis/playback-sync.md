# KawaPlayer: 再生の同期（実装後の仕様）

## 概要

KawaPlayer が、動画の再生をインスタンスの全員でどう合わせているかの記録です。#228 の方針（[docs/design/228-playback-sync/](../design/228-playback-sync/README.md)）で決めて実装した、次の子の issue のあとの動きを書きます。

| issue | 中身 |
| --- | --- |
| #237 | 位置の計算の時計を、VRChat のサーバーの時刻にした |
| #234 | オーナーが替わったときに、全員が先頭に戻らないようにした |
| #235 | 時刻合わせを、1 秒ごと・0.9 秒の境目・バッファ中は待つ、にした |
| #232 | 読み込み直しで、エラーや読み込み中で止まった自分の画面を戻せるようにした |
| #236 | ワールドに置く、全員の読み込み直しのボタンを足した |

変える前の動きと、VizVid（VVMW）との比較は [comparison.md](../design/228-playback-sync/comparison.md) にあります。

**関連ファイル**:
```
Runtime/Internal/
    ├── Controller.cs          再生・一時停止・シーク、読み込み直し、間引き
    ├── Controller.Sync.cs     同期する値、時計、時刻合わせ、受け取り（OnDeserialization）
    ├── Controller.Events.cs   プレイヤーの知らせ（準備完了・再生・エラーとリトライ）
    └── UI/UIController.cs     読み込み直しのボタン、全員の読み込み直しのボタン
Prefabs/GlobalReloadButton.prefab  全員の読み込み直しのボタン（制作者がワールドに置く）
```

## 共有する値

同期は手動（`BehaviourSyncMode.Manual`）で、値を書けるのは `Controller` のオーナーだけです。オーナーが `RequestSerialization` を呼ぶと、VRChat が送る直前に `OnPreSerialization` を呼び、ほかの人の側で `OnDeserialization` が呼ばれます。

| 値 | 型 | 中身 |
| --- | --- | --- |
| `_syncedState` | byte | 止まっている・再生・一時停止 |
| `_title`・`_url`・`_trackExtension` | string・VRCUrl・byte[] | 今の曲。`OnPreSerialization` が、オーナーの今の曲（`Track`）から作る |
| `_trackVersion` | int | 曲の版。オーナーが新しい曲を始めるたびに 1 増える。受け取った人は、版が変わったときだけ読み込む |
| `_handlerIndex`・`_handlerFromTrack` | int・bool | 使うプレイヤーと、それが曲のために切り替えたものか |
| `_syncedVideoTime` | float | 共有の位置（秒） |
| `_syncedServerTimeMs` | int | `_syncedVideoTime` を取ったときのサーバーの時刻（ミリ秒）。0 は「共有の時刻がまだない」 |
| `_speed`・`_loop`・`_repeat` | float・bool・ulong | 速度、ループ、区間リピート |

## 時計と位置の計算

全員が、同じ式で今の位置を計算します（オーナーも同じ）。

```
目標の位置 = _syncedVideoTime + 経過 × 速度 + 自分の遅延（LocalDelay）
経過 = CalculateServerDeltaTime(GetServerTimeInSeconds(), _syncedServerTimeMs × 0.001)
```

一時停止のあいだは、経過を足しません。

- **サーバーの時刻を使う理由：** 以前は `GetNetworkDateTime` を使っていました。VRChat の日時の同期に失敗したクライアント（ログに `Failed to sync network DateTime`）では、それが手元の時計のままになり、その人だけが時計のずれの分ずれ続けました（#237）。
- **一巡：** ミリ秒の値は 32 ビットで一巡するので、引き算はせず `CalculateServerDeltaTime` を使います。引数は秒です。
- **0 の扱い：** 0 は「共有の時刻がまだない」に使います。書く時刻がちょうど 0 なら 1 にします。
- **古い版と混ざらないように：** 同期する値の型を変えた（long から int）ので、古い版で始まったインスタンスには、新しい版の人は入れません。PC と Quest は別々のビルドで同じインスタンスに入るので、両方を同じ版で作り直す必要があります。

## オーナーが値を送るとき

| きっかけ | 送るもの |
| --- | --- |
| 新しい曲を始める（`PlayTrack` など） | 曲、版、状態。共有の時刻は「まだない」に戻す（前の曲がエラーで止まっていても） |
| 始めた曲の準備ができた | 共有の時刻が「まだない」ときだけ、位置 0 とそのときの時刻 |
| 一時停止・再生（オーナーの操作） | そのときの位置と時刻、状態 |
| シーク（`SetTime`、利用者の操作） | シークした位置と時刻 |
| 速度の変更 | 今の位置と時刻、速度 |
| ループで先頭に戻った | 位置 0 と時刻 |
| 止める | 状態。共有の時刻を消す |

次のときは、オーナーでも値を送りません。

- 読み込み直しの途中。その準備完了でも、共有の時刻があれば送らない（ないときは、上の表のとおり位置 0 を送る）
- 準備完了の中で動画を始めるとき（再生の知らせから送らない）
- 時刻合わせで、自分の動画を共有の時刻に合わせるとき（`SeekLocal`）

## 準備ができたとき

`AfterVideoReady` では、共有の状態に合わせて再生・停止したあと、位置を次のように決めます。

- **オーナーで、共有の時刻がまだない：** いま始めた曲です。位置 0 を共有します。
- **それ以外：** 共有の時刻に合わせます。読み込み直し、エラーのあとのリトライ、後から入った人、読み込み中にオーナーを引き継いだ人のどれでも同じです。この合わせ方は境目なしで、必ず合わせます。オーナーより遅れて準備できた人が、遅れたままにならないようにするためです。

以前は、オーナーが読み込み直し以外の読み込みを終えると位置 0 を共有していました。そのため、読み込み中の人にオーナーが替わったときや、オーナーがエラーからリトライしたときに、全員が先頭に戻っていました（#234）。

## 時刻合わせ（ずれの補正）

| 項目 | 値 |
| --- | --- |
| 確かめる間隔 | 1 秒（再生中だけ） |
| シークする境目 | 目標とのずれが 0.9 秒（実際の時間。位置のずれを速度で割る） |
| バッファ中 | 前の確かめから位置が動いていなければ、シークしない |
| 新しい共有の時刻を受け取った | 必ず合わせる（オーナーのシーク・一時停止・再生・速度の変更） |
| ほかの同期の値だけを受け取った（ループなど） | ふだんの確かめと同じ。0.9 秒以上ずれていればシークする |
| 値を送るか | 送らない（`SeekLocal`） |

境目が 0.9 秒なので、0.9 秒より小さなずれは直しません。回線がよいときは、もともと大きくずれません（Build & Test では 0.1 秒以内でした）。シークにはふつう 0.3 秒より長くかかるので、以前の「5 秒ごと、0.3 秒以上」では、シークのたびにまたずれて、シークを繰り返すおそれがありました（#235）。

## 読み込み直し

スクリーンの左の列と、タブレットの KawaPlayer アプリの **読み込み直し** は、押した人の画面だけのものです。値は何も送りません（#232）。

| 場面 | 動き |
| --- | --- |
| 共有の状態が止まっている | 何もしない。ボタンは押せない |
| 読み込み中で、始めてから 15 秒たっていない | 何もしない。ボタンは押せない（遅いだけの読み込みを最初からにしないため） |
| エラーで止まっている、再生中、一時停止中、読み込み中で 15 秒たった | 読み直す |

- **読み直す曲：** オーナーではない人は、受け取った曲を、受け取ったプレイヤーで読み直します。オーナーとローカルモードは、自分の今の曲（`Track`）を、今のプレイヤーで読み直します。オーナーの同期する曲の値は送るときに作られるので、手元では古いか空のことがあるためです。
- **リトライとフォールバック：** 0 からやり直します。フォールバックを解くとプレイヤーが止まるので、その前に「読み込み直し中」の印を立てます。そうしないと、オーナーが止めたことになり、曲と共有の時刻が消えます。
- **準備ができたら：** 共有の状態（再生・一時停止）と、共有の時刻に合わせます（「準備ができたとき」）。
- **間引き：** 読み込み直しとリトライは、この `Controller` の前の読み込みから 5.1 秒あけます（VRChat は 5 秒以内の 2 回目の読み込みを断るため）。待っているあいだの頼み（押した、速度や画質を変えた）は、1 回にまとめます。走るときに状態を見直し、全員が止まっていれば読みません。最後の頼みより後に別の読み込み（エラーのあとのリトライや、新しい曲）が始まっていれば、それにまとめて読みません。同じ 5.1 秒に予約されたリトライと重なって、続けて 2 回読み込まないようにするためです。その読み込みより後に頼みがあれば、その読み込みから 5.1 秒たってから読み直します。待ちが終わるたびに、最後の読み込みと最後の頼みを見直すので、待っているあいだに読み込みが始まっても、頼みは落ちません。ほかの `Controller` や、ふだんの曲の切り替えとの重なりは防ぎません。
- **速度と画質の変更：** AVPro で速度や最大の画質を変えると、読み込み直しが要ります（`ReloadForSettings`）。読み込み中なら、その読み込みの準備ができてから読み直すので、変更は落ちません。その前に別の読み込み（エラーのあとのリトライや、新しい曲）が始まれば、そちらが今の設定で読むので、読み直しません。
- **権限：** 読み込み直しは、PermissionManagement の権限の対象です（#233 で外す予定）。

## 全員の読み込み直し

ワールドの制作者が置く **Global Reload Button**（`Prefabs/GlobalReloadButton.prefab`）は、インスタンスの全員に、それぞれの読み込み直しをさせます（#236）。ライブ配信は位置を合わせないので、遅れが人ごとにたまります。そのときに、全員を配信の今の位置から取り直させるためのものです。普段は要らないので、スクリーンとタブレットの画面にはありません。

| 項目 | 動き |
| --- | --- |
| 押せるとき | 共有の状態が止まっていない（`Controller.CanGlobalReload`）。自分が送ってから 15 秒は押せない。真ん中の文字が、押せる（RELOAD ALL）・送ったあと（RELOADING）・全員が止まっている（NO VIDEO）・権限がない（NO ACCESS、赤い ×）を示し、押せないあいだはアイコンが薄くなる |
| 確認 | ない。1 回押すと送る。押せる人は、置く場所と権限で絞る（VizVid の Global Sync Button と同じ） |
| 権限 | 押すときと、1 秒ごとに `BeforeUserGlobalReload` を聞き手に送る。PermissionManagement は Editor 以上でなければ断り、ボタンは押せなくなって、赤い × と NO ACCESS を出す。押す前から押せないと分かり、権限が変われば 1 秒ほどで表示も変わる |
| 送るもの | ネットワークのイベント（`OnGlobalReload`、全員あて、送った人も含む）だけ。同期する値は変えない。ローカルモードでは、自分だけ読み直す |
| 受けた人 | 自分の読み込み直し（`Reload`）と同じ。共有の状態が止まっていれば読まず、読み込みを始めて 15 秒たっていなければ読まず、5.1 秒の間引きを通る |

- **15 秒待つ理由：** 受けた人は、読み込みを始めて 15 秒は読み直しません。それより早い 2 回目は、読み込みを終えた人だけをまた読み直させます。
- **ボタンの作り：** Controller Bar と同じく、`YamaPlayerSubController` の下に、ボタンだけの `UIController` があります。インスペクターで選んだプレイヤーにつながり、色はほかの画面と同じくパレットから決まります（赤い × と NO ACCESS だけは、どの色の組でも赤のままにするため、パレットの役割を持たない）。見た目は六角形の LED 表示です。六角形の枠（`global-reload-frame.png`）の中の画面に、端まで LED の点（`global-reload-leds.png`）が並び、光った点で丸い枠と回る 2 本の矢印（`global-reload.png`）を描きます。文字は 5 × 7 点の LED 文字の帯（`global-reload-text-*.png`）で、英語だけです（翻訳しない）。どの画像も白い形で、色は Unity で付けます。
- **権限の差し込み口：** PermissionManagement は、聞き手をモジュールの UI スロットで各 `UIController` に入れます。ボタンには、そのための空の `Canvas/Modules` があります。
- **受けた側では確かめない：** 送った人の権限は、押した人の画面で確かめるだけです。ほかの操作と同じです。

## エラーとリトライ

この部分は #228 では変えていません。

- **リトライ：** 失敗すると、最大 5 回まで、前の読み込みから 5.1 秒あけて試します。
- **リトライしないエラー：** Access Denied と Invalid URL は試しません。
- **フォールバック：** 1 回目の Player Error で、AVPro と Unity Video Player のもう一方に切り替えます。
- **使い切ったとき：** 自分の画面だけ止まったままになります。読み込み直しで戻せます（上の表）。

## オーナーが替わるとき

VRChat がオーナーを替えても、`Controller` は聞き手に知らせるだけです。新しいオーナーは、共有の時刻をそのまま使います。読み込み中にオーナーを引き継いだ人も、準備ができたら共有の時刻に合わせ、位置 0 は送りません（「準備ができたとき」）。

## ローカルモード

`IsLocal` の KawaPlayer は、値を送りも受け取りもしません。共有の時刻がないので、時刻合わせは何もしません。読み込み直しは、自分の今の曲で行います。

## 確かめ方

確かめる場面（T1〜T19）は、方針の文書の [§6](../design/228-playback-sync/README.md#6-確かめ方) にあります。実装のときに Unity（ClientSim）と VRChat の Build & Test（同じ PC の 2〜3 クライアント）で確かめたことは、それぞれの PR（#238・#239・#240・#232 の PR）に書きました。
