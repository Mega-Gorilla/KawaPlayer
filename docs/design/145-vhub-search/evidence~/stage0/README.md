# 段階 0 の仕掛けと記録（2026-11-11）

VHub の検索（#145）の段階 0 で、VRChat の中での入力のしかたと、打った文字の届き方を確かめたときのものです。結果は、計画書の 6.3 節にまとめてあります。このときの初期値は、検索用の URL に案内文と `→` を続けた形（経路は `/r/search`）でした。結果を受けて、計画は「URL だけを入れる」「経路を `/r/s?q=` に短くする」に改めています。このフォルダーは `~` で終わるので、Unity は読み込みません。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `SearchProbe.cs.txt` | 記録用の U#。テスト用のシーンに置く。入力欄に初期値を入れ、確定された URL と、読み込みの結果を `[KSP]` の行でログに書く |
| `sp_scene.cs.txt` | Unity のエディターで流す C#。テスト用ワールドの写しに、入力欄 2 つと `SearchProbe` を置く |
| `sp_program.cs.txt` | Unity のエディターで流す C#。`SearchProbe` の U# のプログラムのアセットを作る |
| `search_server.py` | この PC だけで待つ、検索の代役のサーバー。届いた要求の行をそのまま記録し、60 件の作り物の結果を返す |
| `vrc_type.ps1` | テスト用の VRChat の窓が前にあるときだけ、文字とキーを送る |
| `cases.txt` | 打った文字。1 行が 1 件で、`前に押すキー|打つ文字` |
| `probe.txt` | VRChat のログから取り出した `[KSP]` の行（10 件を流した回） |
| `server.jsonl` | 代役のサーバーが記録した要求（同じ回） |

## 流し方

1. `SearchProbe.cs.txt` を `.cs` にして、テスト用プロジェクトの `Assets/` の下の一時フォルダーに置き、`sp_program.cs.txt` と `sp_scene.cs.txt` をエディターで流す（ポートの番号 `__PORT__` を置き換える）。
2. VRChat SDK でワールドをビルドする。
3. `python search_server.py <ポート> <記録のファイル>` でサーバーを立てる。
4. Build & Test と同じ引数で VRChat を 1 台起動する。
5. ログに `[KSP] focus N`・`press N`・`type N`・`enter N` が出るたびに、窓を前に出す・クリックする・`cases.txt` の N 行目を打つ・Enter を押す。`[KSP] shot N` で窓を撮る。
6. 終わったら VRChat を閉じ、一時フォルダーをごみ箱に移す。

`[KSP] partA done` までは、クリックも入力も要りません（初期値の届き方、無効のあいだに値を入れた入力欄、応答の読み取りの時間）。

## 記録の読み方

- `probe.txt` の `entered N url=[…]` が、確定したときに入力欄が持っていた URL です。`codes N` は、`?q=` より後ろの文字のコードです。
- `server.jsonl` の `line_ascii` が、届いた要求の行です。`word` は、計画書の 4.1 の順で取り出した検索語です。
- `json N … parse_ms=… walk_ms=…` が、応答の解析（5 回）と、60 件の項目の取り出しにかかった時間です。
- `loaderror N` は、VRChat が読み込みを断ったときです（`%` を含む 6 件目）。このとき、サーバーに要求は届いていません。

クライアントを閉じるときに出る Udon の例外（映像のプレイヤーの終了の途中のもの）は、この確認とは関係がありません。
