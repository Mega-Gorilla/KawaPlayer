**KawaPlayer 1.3.3** — YYYY-MM-DD

迷子札の版です。

メニューで置いたデバイスは、生まれたときから自分の KawaPlayer を知っています。それでもはぐれた部品は、ビルドのログが名前を呼んで探してくれます。置き忘れたタブレットは、時間が来ればひとりで帰ります（門限を決めれば、ですが）。

ついでに、YamaPlayer の時代から押し入れにしまわれていた、使っていない欄と文言の大掃除もしました。遊ぶ人の目に入る変化は、ほとんど曲名の色だけです。

## 更新する前に、これだけは読んでね

* **ワールドの中の変化は、ビルドし直すと届きます。** 曲の一覧の曲名の色と、権限の説明の色と、自作の UI の色塗りです。ほかは Unity の中の話なので、更新して開けばすぐ効きます。
* **PC と Quest の片方だけを作り直しても、これまでどおり一緒に遊べます。** 同期するデータは 1.3.2 と同じです。
* **自分のスクリプトから KawaPlayer を呼んでいる人は、下の「自分のスクリプトから KawaPlayer を呼んでいる人へ」を見てください。** イベントの名前が 1 つ変わり、使っていない文言のキーが消えています。（#296・#298）
* **VRChat SDK を 3.10.5 に上げる人へ（KawaPlayer のせいではありません）：** SDK のサンプルの **VRCWorld** を置いたワールドは、アップロードの前のビルドが `AssignSceneNetworkIDs`（`Failed to assign network IDs`）で止まることがあります。
  * 3.10.5 で、VRCWorld に UdonBehaviour（WorldQualitySettings）が 1 つ増え、シーンに記録されたネットワーク ID と合わなくなるためです。
  * **VRChat SDK > Utilities > Network ID Import and Export Utility** で、VRCWorld の記録を今の部品に合わせると直ります。ID は変えなくて大丈夫です。
  * KawaPlayer と一緒に SDK を上げる人が多そうなので、念のため。

## 変わったこと

* **`GameObject > KawaPlayer` で置いたデバイスが、最初から KawaPlayer を選んだ状態になりました。** タブレット・Sub Screen・Controller Bar・Playlist Panel・全員リロードボタンが対象です。（#297）
  * KawaPlayer の中に置けば、その KawaPlayer。外に置けば、シーンにある 1 つだけの KawaPlayer。
  * 決められないとき（KawaPlayer が 0 個か 2 つ以上）は、これまでどおり空のままです。わけは、ログが教えてくれます。
  * プレハブをドラッグして置いたときと、もう置いてあるデバイスは、これまでどおりです。
  * 「置いたタブレットが動かない！」の、いちばんよくある原因がひとつ減りました。
* **KawaPlayer につながっていない部品を、ビルドのログが名指しで教えてくれるようになりました。** これまでの `Controller not found on UIController` は、犯人の名前を伏せていました。（#295）
  * **KawaPlayer** の欄が空のデバイスは、Hierarchy のパスと「インスペクターで KawaPlayer を選んで」が、デバイスごとに 1 件出ます。
  * 欄は入っているのに一部がつながっていないデバイス（プレハブの更新で部品が増えたときなど）は、どこが空かと「いったん空にしてから選び直して」が出ます。同じ KawaPlayer を選び直すだけでは直らないので、ご注意を。
  * Play や VRChat のログのエラーにも、部品のパスが出ます。
* **タブレットの「放置で元の位置に戻す (秒)」が、チェックと分の欄に分かれました。** 「0 のときは無効」という、知る人ぞ知る決まりはおしまいです。（#289）
  * **放置したら元の位置に戻す** をオンにすると、**戻すまでの時間 (分)** が出ます。オンにしたときは 5 分で、1 分から決められます。
  * 前に秒で入れていた値は、分で表示されます（120 秒なら 2 分）。動きは変わりません。

使い方ガイドの[タブレット](https://github.com/Mega-Gorilla/KawaPlayer/blob/develop/docs/guide/tablet.md)・クイックスタート・全員リロードボタン・インストールのページも、合わせて直しました。

## 直したこと

* **曲の一覧の、再生中でない曲名が、配色の文字色になりました。** これまでは真っ白で、プレハブの透明度（75%）まで消えていました。真っ白に燃え尽きていた曲名に、色が戻ります。再生中の曲名は、これまでどおり主色です。（#293）
* **権限の説明文の役割名が、インスペクターで選んだ役割の色で出るようになりました。** これまでは色が決め打ちで、色を変えても印だけが変わっていました。（#293）
* **ビルドが、UIController のない自作の UI にも、配色の色を塗るようになりました。** 「今すぐ反映」では塗られるのに、ビルドだけが素通りしていました。同梱の UI の見た目は変わりません。（#293）
* **インスペクターの文字を直しました。**（#293）
  * カラーセットがないときの案内が、そこにない「追加」ボタンを指していました。今は「編集」を指します。
  * プレイモード中の案内、再生間隔の「秒」、更新の確認の「OK」が、エディタの言語（9 言語）で出ます。

## 中身の改善（見た目は変わりません）

* **UIController の、どこからも使われていない欄を 4 つ消しました。** 配色の副色と、ReSync・AVPro の文字を指していた欄です。色も文字も、これまでどおりです。（#296）
* **どこからも使われていない文言のキーを 139 個消しました。** YamaPlayer の古いインスペクターの文言と、カラオケや動画の検索など、KawaPlayer にない機能の文言です。翻訳ファイルが 1,215 行やせました。（#298）
  * 9 言語の画面の文字が前と同じことは、VRChat の中で 1 つずつ比べてあります。違ったのはタブレットの時計だけでした（時間は進むので）。

## 自分のスクリプトから KawaPlayer を呼んでいる人へ

* **`SetLanguageToUkranian` は `SetLanguageToUkrainian` になりました。** つづりを直しました。古い名前は残していないので、`SendCustomEvent` で呼んでいるときは書き換えてください。（#296）
  * トグルの欄も `_languageUkranianToggle` から `_languageUkrainianToggle` になりました。同梱のプレハブは直してあります。
  * 自作の UI や、シーンでこの欄に別のトグルを入れていたときは、その設定が外れます。`UIController` のインスペクターの **Language Ukrainian Toggle** で選び直してください。
* **KawaPlayer の本体の文言を借りていたら、消えていないか確かめてください。** 自作の UI やモジュールで、`GetTranslation` や `EditorLocalization.Get` を使って本体のキー（`msg.loading` など）を読んでいた場合です。（#298）
  * 消えたキーは、実行時は空の文字、エディターではキーの名前のまま出ます。
  * 本体の文言は KawaPlayer の画面のためのものです。自分の文言ファイル（モジュールの `Localization.Runtime.json` など）に移してください。

## 入手方法

VCC（VRChat Creator Companion）から入れます。更新の前に、上の「更新する前に、これだけは読んでね」を見てください。

KawaPlayer のリポジトリを追加済みなら、1.3.3 はもう更新候補に出ています。まだの人は、下の URL をブラウザのアドレスバーに貼って Enter を押してください。VCC が開き、リポジトリが追加されます。あとは **Manage Project** からプロジェクトに **Add** するだけです。

```
vcc://vpm/addRepo?url=https://mega-gorilla.github.io/vpm-repos/index.json
```

VCC が開かない場合は、**Settings > Packages > Add Repository** に `https://mega-gorilla.github.io/vpm-repos/index.json` を入力してください。

*English:*

The name-tag release. Devices placed from the menu now know their player from the start, the build log calls out any part that has wandered off, and a tablet left behind can find its own way home. We also cleared out the fields and text left unused since the YamaPlayer days. Players will mostly notice one thing: the colour of the track titles.

**Read this before you update:**

* What changes in the world reaches players once you rebuild: the track titles' colour, the permission description's colours, and the colouring of a UI of your own. Everything else happens in Unity and works as soon as you update.
* The synced data is the same as in 1.3.2, so PC and Quest builds still play together when only one is rebuilt.
* If your own scripts call KawaPlayer, see For your own scripts: one event was renamed and unused translation keys are gone.
* **Updating the VRChat SDK to 3.10.5?** Not a KawaPlayer change, but you may meet it at the same time. A world with the SDK's sample **VRCWorld** may stop at `AssignSceneNetworkIDs` (`Failed to assign network IDs`) before upload, because 3.10.5 adds an UdonBehaviour (WorldQualitySettings) to VRCWorld. Bring VRCWorld's record up to date in **VRChat SDK > Utilities > Network ID Import and Export Utility**; the IDs can stay the same.

**What's changed:**

* Devices placed from **GameObject > KawaPlayer** (tablet, Sub Screen, Controller Bar, Playlist Panel, Global Reload Button) come with their player chosen: the KawaPlayer they are placed inside, or else the scene's only one. With none or several, the field stays empty and the log says why. Devices dragged in from their prefabs, and those already placed, are unchanged.
* The build log names each device that is not connected to a player, once per device, with its path and how to fix it. The nameless `Controller not found on UIController` is gone, and run-time errors show the part's path too.
* The tablet's "Return when idle (s)", where 0 meant off, is now a **Return when left alone** toggle with a **Time before return (min)** field. It starts at 5 minutes when turned on (1 or more). Seconds set before show up as minutes and work as before.

**What's fixed:**

* Track titles that are not playing take the colour set's text colour at 75% opacity instead of plain white, on the screen and the Playlist Panel. The playing one keeps the primary colour.
* The role names in the permission description take the role colours set in the inspector.
* The build now colours a UI of your own that has no UIController, as Apply Colors Now already did.
* Inspector text: with no colour set to choose, the inspectors point to Edit, not to an Add button they do not have. The play-mode notice, the interval's unit and the update dialog's OK follow the editor language.

**Under the hood:**

* Four UIController fields that nothing read are gone.
* 139 translation keys that nothing read are gone: YamaPlayer's old inspector text and text for features KawaPlayer does not have. Every text looks the same in all nine languages, compared one by one in VRChat (only the tablet's clock differed; time flies).

**For your own scripts:**

* `SetLanguageToUkranian` is now `SetLanguageToUkrainian`, with no old name kept, and the toggle's field `_languageUkranianToggle` is now `_languageUkrainianToggle`. The bundled prefabs are updated; on a UI of your own, or where a scene set that field, choose the toggle again in the UIController's inspector.
* If a UI or module of your own read KawaPlayer's own translation keys (such as `msg.loading`), check they are still there: a removed key reads as an empty string at run time and as its own name in the editor. Keep your text in your own translation file.

Seen something odd? Tell us on our [Discord server](https://discord.gg/tkrHek6PvN).
