**KawaPlayer 1.3.4** — 2026-10-29

YamaPlayer から乗り換える人のための、小さな更新です。

VCC で KawaPlayer を足すと、入っている YamaPlayer を VCC が外してくれるようになりました。「YamaPlayer を外す前に足してしまって、KawaPlayer が壊れた」という事故は、これでもう起きません。中身は 1.3.3 と同じで、変わったのは VCC で入れるときの動きだけです。

## 更新する前に、これだけは読んでね

* **ワールドの中の動き（Udon）は 1.3.3 と同じです。** この更新のために、ワールドをビルドし直す必要はありません。PC と Quest で 1.3.3 と 1.3.4 が混ざっても、そのまま一緒に遊べます。
* ワールドの中の更新履歴を新しくしたいときだけ、ビルドし直してアップロードしてください。
* **YamaPlayer をまだ残しておきたいプロジェクトには、足さないでください。** KawaPlayer を足すと、YamaPlayer は確認なしに外れます。もともと一緒には入れられないので（下の「なぜ」）、乗り換えると決めたプロジェクトで足してください。戻したいときは、KawaPlayer を外して YamaPlayer を足し直せば元どおりです。

## 変わったこと

* **VCC で KawaPlayer を足すと、入っている YamaPlayer を VCC が自動で外すようになりました。**（#322）
  * **なぜ：** KawaPlayer は YamaPlayer から分かれたので、ファイルの GUID を 152 個と、アセンブリの名前を共有しています。両方が入るとコンパイルエラーになるうえ、Unity は後から入ったほうのファイルの GUID を書き換えます。YamaPlayer を外す前に KawaPlayer を足すと、YamaPlayer を外しても KawaPlayer は壊れたままでした。エラーは 190 件。あまり数えたくない数です。
  * **これからは：** VCC が KawaPlayer を足すときに YamaPlayer を外すので、両方が入る瞬間がありません。確認の画面は出ず、VCC のログ（**Logs**）にこう出ます。

    ```
    [INF] Looking for Legacy Packages to Remove for com.vhub.kawaplayer
    [INF] UnityProject removing VPM package net.kwxxw.yama-stream at 14:16
    ```

  * **VCC を通らないとき：** YamaPlayer を .unitypackage で入れていたときは、自動では外れません。先に YamaPlayer を外してください。
* **README の「YamaPlayer からの移行」を書き直しました。** 自動で外れることに合わせて、乗り換えたあとにすることを足しています。（#322）
  * シーンの赤い YamaPlayer（Missing Prefab）を消して、**GameObject > KawaPlayer > Main** で KawaPlayer を置き直します。YamaPlayer の設定とプレイリストは引き継がれません。
  * 開いた直後に Console に出る `error CS2001`（消えた YamaPlayer のファイル）は、次のコンパイルで消えます。慌てなくて大丈夫です。
  * KawaPlayer のエラーが消えないときは、Unity を閉じて KawaPlayer を外し、足し直します。1.3.3 までの版で、外す前に足してしまった人も、これで直ります。

## 困ったら

「こんなことが起きた！」があれば、気軽に [Discord サーバー](https://discord.gg/tkrHek6PvN) で教えてください。あなたの報告が、次のリリースを作ります。今回の更新も、乗り換えた方の報告から生まれました。

## 入手方法

VCC（VRChat Creator Companion）から入れます。KawaPlayer のリポジトリを追加済みなら、1.3.4 はもう更新候補に出ています。まだの人は、下の URL をブラウザのアドレスバーに貼って Enter を押してください。VCC が開き、リポジトリが追加されます。あとは **Manage Project** からプロジェクトに **Add** するだけです。

```
vcc://vpm/addRepo?url=https://mega-gorilla.github.io/vpm-repos/index.json
```

VCC が開かない場合は、**Settings > Packages > Add Repository** に `https://mega-gorilla.github.io/vpm-repos/index.json` を入力してください。

*English:*

A small update for people moving from YamaPlayer. Nothing changes inside the world; only how VCC installs KawaPlayer.

**What's changed:**

* **Adding KawaPlayer in VCC now removes YamaPlayer from the project.**
  * **Why:** KawaPlayer shares 152 file GUIDs and its assembly names with YamaPlayer. With both installed, the scripts do not compile, and Unity rewrites the GUIDs of whichever package came second. Adding KawaPlayer before removing YamaPlayer left KawaPlayer broken even after YamaPlayer was gone.
  * **Now:** VCC removes YamaPlayer as it adds KawaPlayer (the package's `legacyPackages`), with no prompt. VCC's log says `UnityProject removing VPM package net.kwxxw.yama-stream`.
  * **Not through VCC:** If YamaPlayer came from a .unitypackage, remove it yourself first.
  * **Keeping YamaPlayer:** Do not add KawaPlayer to a project where you still want YamaPlayer. To go back, remove KawaPlayer and add YamaPlayer again.
* **The README's "Moving from YamaPlayer" is rewritten:** replace the red YamaPlayer (Missing Prefab) in the scene with **GameObject > KawaPlayer > Main** (its settings and playlists do not carry over), the `error CS2001` right after opening clears on the next compile, and if KawaPlayer's errors stay, remove KawaPlayer and add it again.

You do not need to rebuild your world for this update. Anything odd? Tell us on our [Discord server](https://discord.gg/tkrHek6PvN).
