KawaPlayer 1.2.0 は、VHub プレイリストを「ワールドの一部」として扱えるようにするリリースです。これまでプレイリストの読み込みは、URL を入れるとキューに曲が流し込まれて、再生し終わると消えていく一時的なものでした。1.2.0 では読み込んだプレイリストがプレイヤーのプレイリスト一覧に並び、曲を選び直したり、更新したり、いらなくなったら消したりできます。Unity 側でも、共有 URL を貼るだけで VHub のプレイリストをワールドに焼き込めるようになりました。

4 か月ぶりの更新で、1.1.2 以降にマージした変更は 30 件を超えます。細かい修正は省いて、使い方が変わるところを中心にまとめています。

## VHub プレイリストの読み込み

* **プレイリスト専用の入力欄は無くなり、いつもの URL 欄に統合されました。** 動画 URL を入れる場所に VHub の共有 URL を入れれば、プレイヤーが自分で見分けて読み込みます。停止中の画面上部には「この欄に何を入れられるか」の案内と、プレイヤー名・バージョンが出るようになったので、初めて触る人にも入り口が分かるはずです。
* **読み込んだプレイリストは、キューではなくプレイリスト一覧に入ります。** 最後の曲まで再生しても消えず、先頭に戻ってループします。途中の曲をタップして選び直すこともできます。1 つのワールドに同時に持てる VHub プレイリストは標準で 5 件で、ワールド制作者は Unity 上で増減できます。
* **一覧のプレイリスト名の横に「更新」と「削除」のボタンが付きました。** VHub 側でプレイリストを編集したら、その場で更新ボタンを押すだけで最新の内容になります。同じ共有 URL をもう一度入力した場合も、新しく追加されるのではなく既存のものが更新され、「更新しました」と表示されます。
* **5 件が埋まった状態で 6 件目を読み込もうとすると、どのプレイリストが消えるかを確認する画面が出ます。** 以前は一番古いものが黙って入れ替わっていました。確認を出している間に別の人が先に同じ枠を使ってしまった場合は、確認したものと違うプレイリストを消さないように読み込みを中止し、やり直しをお願いする文言が出ます。
* **読み込みの結果が画面に出るようになりました。** 追加された曲数、飛ばした曲数、失敗したときはその理由（見つからない・取得できない・共有 URL ではない など）を表示します。以前は成功しても失敗しても無言でした。
* **プレイリストの読み込みが再生権限（PermissionManagement）の対象になりました。** 再生を許可していない人は、プレイリストも読み込めません。
* プレイリストを削除すると、空になった詳細画面に留まらず一覧へ戻るようになりました。

## Playlist Editor（Unity 側）

* **VHub プレイリストを Unity 上で取り込めるようになりました。** Playlist Editor に共有 URL を貼って取り込むと、その時点の内容が固定のプレイリストとしてワールドに焼き込まれます。VRChat 内で読み込む方式と違ってサーバーに問い合わせないので、ワールドの初期プレイリストとして使えます。取得元の URL を覚えておくので、同じ URL でもう一度取り込めば内容を更新できます。
* YouTube のプレイリストを取り込みに失敗したとき、それまで入っていた曲まで消えてしまうことがありました。失敗したら元の内容をそのまま残します。
* 取り込みを適用したあとに選択が別の行へ飛んだり、一覧のハイライトと右側の詳細がずれたりする問題を直しました。
* yt-dlp に渡す URL は、コマンドライン文字列に組み立てるのではなく引数として直接渡すようにしました。URL に含まれる文字で動作が変わることがなくなります。

## 画面まわり

* **確認ダイアログが、別の操作に上書きされなくなりました。** 例えば「再生中の動画を切り替えますか？」と聞いている最中に、裏で別の URL を入れても、質問はそのまま残ります。以前は質問が差し替わって、答えを待っている側が永遠に待ち続けることがありました。
* 確認ダイアログの「Unity Video Player / AVPro Video Player / 画像表示」の選択肢が、縦 3 段ではなく横 1 行に並びます。設定画面の同じ選択肢とそろえました。
* YouTube の動画を再生できなかったとき、状況に応じた案内を出します。VHub プレイリスト経由で再生した YouTube 動画でも同じ案内が出ます。
* Playlist Panel（別置きのプレイリストパネル）で、キュー・履歴・プレイリストのタブが表示されず切り替えられなかった問題を直しました。
* プレイリスト一覧のヘッダとトラック行のボタンを、中身に合った大きさにしました。名前が長いプレイリストでも数文字しか見えない、ということがなくなります。
* 日本語と中国語の文言で、英単語の前後に入っていた半角スペースのせいで本文が不自然な位置で折り返されていたのを直しました。

## デフォルト動画 URL

* **設定する権限が無い人には、設定欄を見せる代わりに理由を表示します。** 以前は権限が無いと入力欄が理由も無く消えていました。権限がある人には、入力欄そのものがボタンになりました。押すと VRChat の入力画面が今の設定値が入った状態で開き、確定すればそのまま保存されます（保存ボタンはありません）。

## 本家 YamaPlayer の更新を取り込みました

2026-08-03 時点の YamaPlayer `develop` に追従しています。目に見える変化は次のとおりです。

* エラーが起きたあとに停止できなくなる不具合が直っています。
* 動画の切り替えとフォールバック（別のプレイヤーで再生し直す処理）が安定しました。
* 一時停止中に動画の準備が終わっても、勝手に再生が始まらなくなりました（TimelineSync）。
* エディタのプレイリスト編集画面の不具合が直っています。

## 知っておいてほしいこと

* **複数人での同期と途中参加の動作は、このリリースでは検証していません。** 開発側で複数アカウントをそろえられなかったためです。プレイリストが人によって違って見える、あとから入った人に反映されない、といったことがあれば [#68](https://github.com/Mega-Gorilla/KawaPlayer/issues/68) のコメントか新しい issue で教えてください。
* **YouTube の再生に失敗する場合、KawaPlayer 側では直せないことが多いです。** VRChat と YouTube の間の解決処理は環境や時期によって失敗します。1.2.0 で追加した案内は「何が起きているか」を伝えるためのもので、再生できるようにするものではありません。
* デフォルト動画 URL に VHub プレイリストを設定したときは、5 件が埋まっていても確認なしに一番古いものと入れ替わります（[#129](https://github.com/Mega-Gorilla/KawaPlayer/issues/129)）。
* プレイリストを削除したあとに新しく読み込むと、一覧の末尾ではなく削除した位置に入ります（[#128](https://github.com/Mega-Gorilla/KawaPlayer/issues/128)）。
* URL 欄に前回入れた URL が残っていることがあります。VRChat のキーボードをキャンセルで閉じると、その残った URL が再送信されることがあります（[#133](https://github.com/Mega-Gorilla/KawaPlayer/issues/133)）。

## 導入と更新

* VCC を使っている場合は、リポジトリ `https://mega-gorilla.github.io/vpm-repos/index.json` を登録済みなら 1.2.0 が更新候補として出ます。まだの場合の手順は [README](https://github.com/Mega-Gorilla/KawaPlayer#クイックスタート-vcc-推奨) にあります。
* VCC を使わない場合は、このページの `com.vhub.kawaplayer-1.2.0.unitypackage` をダウンロードして Unity にインポートしてください。
* **KawaPlayer は YamaPlayer を置き換えるパッケージです。** 同時にはインストールできません。YamaPlayer からの移行手順は README の「[YamaPlayer からの移行](https://github.com/Mega-Gorilla/KawaPlayer#yamaplayer-からの移行)」を参照してください。
* 1.1.x から更新する場合、シーンに置いた `KawaPlayer.prefab` のインスタンスはそのまま使えます。1.1.x で prefab の中にあった専用の入力欄 `PlaylistLoaderInput` は無くなるので、その GameObject を独自のスクリプトから参照していた場合だけ参照先を外してください。

## English summary

KawaPlayer 1.2.0 turns VHub playlists from a one-shot queue fill into part of the world. A playlist loaded from the URL field (the dedicated playlist field is gone — paste the share URL into the normal URL field) now lands in the playlist list, loops, can be re-picked track by track, refreshed with one button, and deleted. A world holds five of them by default; when all five are taken, the player asks which one you are about to lose instead of silently replacing the oldest. Loading now reports what happened — how many tracks were added, what was skipped, and why a load failed — and respects PermissionManagement.

In Unity, the Playlist Editor can import a VHub playlist from its share URL and bake it into the world as a fixed playlist; importing the same URL again updates it. Confirmation dialogs no longer get hijacked by a second action, the YouTube failure hints now cover VHub-sourced tracks too, the Playlist Panel tabs work again, and the default-URL settings explain themselves when you lack permission. Upstream YamaPlayer changes through 2026-08-03 are included.

Not verified in this release: multi-user sync and late-join behaviour. Please report anything odd there on [#68](https://github.com/Mega-Gorilla/KawaPlayer/issues/68).
