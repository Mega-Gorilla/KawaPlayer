**KawaPlayer 1.3.0** — YYYY-MM-DD

タブレットが来ました。

ワールドの KawaPlayer を、手の中から操作できます。もうスクリーンの前まで歩いていかなくて大丈夫です（運動不足の方はご注意ください）。

ほかにも、みんなの再生がそろいやすくなりました。色は川の青になり、ReSync はちゃんと仕事をするようになりました。今回はかなり盛りだくさんなので、飲み物を片手にどうぞ。

## 更新する前に、これだけは読んでね

* **VRChat Worlds SDK 3.10.2 以上が必要になりました。** SDK が古いプロジェクトは、先に VCC の **Manage Project** で VRChat SDK（Worlds と Base）を上げてから、KawaPlayer を更新してください。（#194）
* **PC と Quest の両方を、1.3.0 でビルドし直して公開してください。** 再生の同期のしくみが変わったので、PC と Quest で KawaPlayer の版が違うと、同じインスタンスにいても、PC の人と Quest の人で再生がそろいません。また、更新の前から開いているインスタンスには、新しい版では入れないことがあります（VRChat が、版の合わないインスタンスから外します）。確かめるときは、新しいインスタンスを立ててください。（#238）
* **「デフォルト URL」は「自動再生」に名前が変わりました。** 中身は同じで、保存した URL もそのまま使えます。見つからなくても、消えたわけではありません。（#174）
* **自分の U# スクリプトから KawaPlayer を呼んでいる人は、下の「自分のスクリプトから KawaPlayer を呼んでいる人へ」を見てください。** 古い名前の API をいくつか消しました。（#254）

## 新しいこと

### 持ち運べる KawaPlayer タブレット

* `GameObject > KawaPlayer > Tablet` で置いて、インスペクターで使う KawaPlayer を選べば準備完了です。何台置いても大丈夫です。（#155）
* **KawaPlayer アプリ：** ワールドの KawaPlayer の画面が、まるごと入っています。再生・シーク・音量・URL・プレイリストを、手元でどうぞ。（#156）
* **画像アプリ：** URL を入れると、タブレットを見ている全員に同じ画像が映ります。最後の 5 枚は一覧に残るので、あとから選び直せます。（#158・#185）
* **「KawaPlayer に送る」を押すと、その画像をワールドのスクリーンに映せます。** 何かを再生中でも、確認なしですぐに切り替わります。度胸のある方向けです。（#187）
* **画像が出ないときは、理由と次にすることを教えてくれます。** サイトに断られたのか、VRChat の設定で許可が要るのかを見分けます。「もう一度読み込む」ボタンも出ます。（#179）
* **訪問者アプリ：** 今いる人、前にいた人、入退室のログ、アバターの顔写真が見られます。顔写真は、ワールド制作者がオフにできます。（#165）
* **設定アプリ：** 明るさ・左右反転・最大解像度・遅延補正・AudioLink・言語など、自分だけに効く設定をここで変えられます。インスタンスオーナーなら、自動再生の URL も決められます。（#160）
* **バージョン情報：** KawaPlayer の版と、この版の主な変更が見られます。（#155）
* **タブレットを縦に持つと、画面も縦になります。** どのアプリも縦向きの配置になり、設定の分類は上のタブに並びます。逆さに持てば、画面も逆さに回ります。KawaPlayer アプリだけは、ボタンが小さくならないように横向きのままです。（#186）
* 開いているアプリと表示中の画像は、見ている全員と、あとから入った人に同期します。（#156・#185）
* ホームボタンの目印は、白い □ です。アプリを開いているあいだは、周りの LED が青く光ります。（#184）
* 裏には、銀の KawaPlayer のロゴがあります。光の当たり方で、金属っぽく浮き上がって見えます。見えないところにも、こだわりました。（#190）
* VR では、触れたところのまま持てます。右手で持つと外側にぶら下がる問題も直しました。（#157・#175）
* 置き忘れたタブレットは、戻すボタンを押すか、しばらく放っておくと元の場所に戻ります（使えるかは、ワールド制作者の設定で決まります）。
* 権限の管理（PermissionManagement）が、タブレットにも効きます。再生の権限がない人は、タブレットからも KawaPlayer に画像を送れません。（#187）

### 全員リロードボタン（ライブイベント向け）

* 押すと、インスタンスの全員が、それぞれの画面で読み込み直します。ライブ配信の遅れが人によってバラバラになったときの、切り札です。（#243）
* **置き方：** モジュール管理で「全員リロードボタン」のモジュールを足してから、`GameObject > KawaPlayer > Global Reload Button` でボタンを置きます。（#249）
* ふつうの動画なら、最初からではなく、今の再生位置から続きます。
* 一度押すと、15 秒は押せません。連打しても、全員が困るだけなので。
* 権限の管理を入れたワールドでは、Editor 以上の人だけが押せます。押せない人には「NO ACCESS」が出ます。
* モジュールが無い、無効になっている、またはプレイヤーを選んでいないボタンは、ビルドで外され、ログに出ます。（#249）
* スクリーンやタブレットには付いていません。要るワールドにだけ置いてください。

### KawaPlayer の色とロゴ

* UI の色を、YamaPlayer のピンクから、KawaPlayer の「川の青」（`#4FC3F7`）に変えました。タブレットも同じ色です。（#162）
* 色は、配色アセット（`Assets/Appearance/KawaPlayerPalette.asset`）の 1 か所で決まります。YamaPlayer の配色も選べます。（#162）
* 何も再生していないとき、スクリーンに KawaPlayer のロゴが出ます。これまでは真っ黒でした。（#179・#190）
  * インスペクターの「待ち受け画像」で、差し替えられます。差し替えた画像には、ロゴを重ねません。
  * 待ち受け画像を作り直して、ビルドでの大きさを 8,099 KB から 27 KB にしました。ダイエット成功です。
* KawaPlayer のロゴ（3 色）と、クイックスタートのポスターを、パッケージの `Media~` に入れました。（#197）
  * ワールドへの掲示や、KawaPlayer の紹介に使えます。販売するワールドへの同梱も OK です。
  * 使える範囲は、`Media~/LICENSE.md` を見てください。

### 再生できないときの「詳細」ボタン

* エラーの下に「詳細」ボタンが出ます。直近のエラーの内容と、問い合わせ先が見られます。その画面のスクリーンショットをもらえると、原因探しがぐっと早くなります。（#171）
* 問い合わせ先の Discord の URL は、コピーできる欄に入っています。ワールドからはリンクを開けないので、欄から写してブラウザに貼ってください。（#171）

## みんなの再生がそろいます

同期のしくみを、まとめて見直しました（#228）。くわしい話は、使い方ガイドの[再生の同期のしくみ](https://github.com/Mega-Gorilla/KawaPlayer/blob/develop/docs/guide/technical/sync.md)にあります。

* 位置を合わせる時計を、VRChat のサーバーの時刻に替えました。VRChat と時計を合わせられなかった人だけ、ずっとずれて再生していた問題が直ります。（#238）
* インスタンスのオーナーが抜けたときや、エラーから読み込み直したときに、全員の動画が先頭に戻ってしまう問題を直しました。（#239）
* ずれを合わせ直すのは、1 秒近くずれたときだけにしました。読み込みが追いついていないあいだは待ちます。映像が何度も引っかかることがなくなります。（#240）
* **ReSync は、押した人の画面だけを読み込み直します。** エラーで止まった画面や、読み込み中のまま進まない画面も戻せます。ほかの人には何も届きません。（#241）
* ReSync は、押して何かが起きるときだけ押せます。押せないときは、アイコンが薄くなります。（#253）
* 権限の管理を入れたワールドでも、ReSync は誰でも押せます。自分の画面だけのものなので。（#242）

## 変わったこと

* ワールドの中で選べる動画プレイヤーを、AVPro にまとめました。Unity Video Player は、AVPro で再生できないときの切り替え先として残っています。（#148）
* **KawaPlayer は、いつも AVPro から始まります。** VHub の曲も AVPro で再生するので、YouTube が 360p に縛られることは、もうありません。（#188）
* 取り込み済みの VHub のプレイリストも、ワールドをビルドし直すだけで AVPro になります。Unity で再生したい曲は、VHub から取り込んでいないプレイリストに入れてください。（#188）
* KawaPlayer のインスペクターから「プレイヤー」の欄をなくしました。プレイヤーの並びは、ビルドのときにそろえます。自動再生(World) の既定のプレイヤーも、AVPro にしました。（#188）
* 画像を映したあとに入れた動画の URL は、AVPro で再生します。続けて画像を映したいときは、設定で「画像」を選んでください。（#187）
* 自動再生の欄の見出しは「自動再生(Global)」です。(Global) は、全員に効く設定の印です。（#174・#222）
* モジュール管理では、自動再生を「自動再生(Owner)」、YamaPlayer から来た AutoPlay を「自動再生(World)」と表示します。(Owner) はインスタンスオーナーが VRChat の中で、(World) はワールド制作者が Unity で、流すものを決めます。（#174）
* モジュール管理と KawaPlayer のインスペクターの一覧に、外部プレイリスト読込（PlaylistLoader）と自動再生(Owner) が、名前付きで出ます。「無効化」はモジュールの部品ごと切り替わり、ビルドでも部品ごと外れます。（#172）
* KawaPlayer に最初から入っているモジュールは、一覧から削除できなくなりました。消すと足し直せないためです。使わないときは、無効化してください。（#172）
* 2 つの自動再生を両方とも有効にすると、モジュール管理とビルドのログにエラーが出ます。どちらが流れるかは入室のタイミング次第の運任せになるので、片方にしてください。ビルドは止まりません。（#172）
* 同じモジュールを 2 つ置くと、モジュール管理・ビルドのログ・KawaPlayer のインスペクターにエラーが出ます。どちらも消さず、ビルドは続けます。（#147・#172）
* 「Access Denied」のときは、「Allow Untrusted URLs」をオンにするよう案内します。それでも流れなければ、ワールドの制作者に連絡するよう伝えます。（#221・#226）
* **ワールド制作者向け：** Access Denied の「詳細」に、VRChat.com の Video Player Allowed Domains に足すドメインが出ます。Public と Group Public のインスタンスでは、そこに載っていない信頼されていないサイトの動画は流れません。（#226）
* VHub のページや「シェア」の URL を入れたときは、「VRChat用URL」を入れるよう案内します。プレイリストエディターの取り込みでも同じです。（#220）
* KawaPlayer のインスペクターに「使い方を見る」ボタンを置きました。GitHub の使い方ガイドが開きます。（#219）
* パッケージから、文書（`docs`）・開発用のファイル・テスト・ポスターの元（`Media~/poster/source`）を外しました。プロジェクトが少し軽くなります。ガイドとポスターの元は、GitHub にあります。（#223・#227）
* 使っていなかった画像 9 枚を、パッケージから消しました。自分の UI で KawaPlayer の `Assets/Images` の画像を使っているときは、参照が外れていないか確かめてください。（#190）

## 直したこと

* AudioLink のモジュールで「デフォルトでAudioLinkを有効にする」がオフのとき、入った人の AudioLink まで止めてしまう問題を直しました。DJ ブースなど、KawaPlayer 以外の音で AudioLink を使っているワールドでも安心です。（#224）
* スクリーンの右の列のタブ（キュー・履歴・プレイリスト）を指すと、文字が少し上がる動きを取り戻しました。YamaPlayer の頃からあったのに、いつの間にか動かなくなっていました。おかえり。タブレットの KawaPlayer アプリと、操作パネル（Playlist Panel）のタブも同じです。（#250）
* PitchShifter（任意のモジュール）で、スピーカーが 2 つ以上あると、2 つ目からずれた音が出ていた問題を直しました。（#202）
* スライドショー（任意のモジュール）を入れたワールドで、止まっているときやライブのときに、シークのツールチップが出たままになる問題を直しました。（#203）
* PlaylistLoader をコンパイルするたびに出ていた警告（CS0414）を、出さないようにしました。（#146）

* 開発者向けの文書を足しました。同期の方針（#229）、同期のしくみ（#251）、デバイスのつながり方（#255）です。設計の文書は、issue の番号のフォルダーに整理しました（#231）。

## 自分のスクリプトから KawaPlayer を呼んでいる人へ

古い名前のまま残していた API を消しました。自分の U# スクリプトから呼んでいるときは、下の表の新しい名前に書き換えてください。（#254）

| 消した API | 代わり |
| --- | --- |
| `Controller.VideoPlayerHandle` | `Controller.Handler` |
| `Controller.MirrorInverse` | `Controller.MirrorFlip` |
| `Controller.Emission` | `Controller.Brightness` |
| `UIController.AddUrlTopToQueueEvent` | `UIController.AddUrlToQueueEvent` |
| `UIController.PlayUrlTopEvent` | `UIController.PlayUrlEvent` |
| `PlaylistLoader.LoadPlaylistFromUrlWithFeedback(url, ui)` | `PlaylistLoader.LoadPlaylistFromUrlWithFeedback(url, ui, null, string.Empty)` |
| `PlaylistLoader.LoadResultQueueUnavailable` | `PlaylistLoader.LoadResultNoSlot`（値は 7 のまま） |
| `Modal.Show(...)` | `Modal.TryShow(...)` |

* `Modal.TryShow` は、ほかの質問が出ているあいだは何も出さずに `false` を返します。これまでの `Show` のように、断ったことを閉じるイベントで知らせることはしません。
* `UIController.ShowMessage` は、表示できたかを `bool` で返すようになりました。戻り値を使わない呼び方は、そのまま動きます。
* `AddUrlToQueueEvent` と `PlayUrlEvent` は、URL の確認ダイアログへの答えです。ダイアログが出ていないときに外から送っても、何も起きません。
* 呼ばれることのなかった `YamaPlayerListener.AfterVideoReloaded` と `PermissionManagementUI.BeforeUserPlayVideo`、何もしない `AutoAssign` 属性を消しました。上書きや指定をしていたときは、その部分を消してください。

## 困ったら

「こんなことが起きた！」があれば、気軽に [Discord サーバー](https://discord.gg/tkrHek6PvN) で教えてください。動画が再生できないときは、「詳細」の画面のスクリーンショットも添えてもらえると、とても助かります。あなたの報告が、次のリリースを作ります。

## 入手方法

VCC（VRChat Creator Companion）から入れます。更新の前に、上の「更新する前に、これだけは読んでね」を見てください。

KawaPlayer のリポジトリを追加済みなら、1.3.0 はもう更新候補に出ています。まだの人は、下の URL をブラウザのアドレスバーに貼って Enter を押すと VCC が開き、リポジトリが追加されます。あとは **Manage Project** からプロジェクトに **Add** するだけです。

```
vcc://vpm/addRepo?url=https://mega-gorilla.github.io/vpm-repos/index.json
```

VCC が開かない場合は、**Settings > Packages > Add Repository** に `https://mega-gorilla.github.io/vpm-repos/index.json` を入力してください。

更新したら、ワールドをビルドし直してアップロードすると反映されます。

*English:*

**Read this before you update:**

* KawaPlayer 1.3.0 needs VRChat Worlds SDK 3.10.2 or later. If your project's SDK is older, update the SDK (Worlds and Base) in VCC first.
* Rebuild and publish both your PC and Quest builds with 1.3.0. If they run different KawaPlayer versions, PC and Quest players in the same instance won't play in step. An instance opened before the update may also turn the new version away, so test in a new instance.
* "Default URL" is now called "Autoplay". Saved URLs carry over.
* If your own scripts call KawaPlayer, a few old API names are gone. See the table above for their replacements.

**What's new:**

* **The KawaPlayer tablet** (`GameObject > KawaPlayer > Tablet`). Control the player from your hand: no more walking to the screen, sorry about your step count. It has apps for these:
  * showing a picture to everyone, and sending it to the big screen;
  * seeing who is here and who has been;
  * your own settings.

  The screen turns as you hold it upright.
* **The Global Reload Button**, for live events. Add its module in Module Manager first, then place the button (`GameObject > KawaPlayer > Global Reload Button`). One press has everyone reload their own screen.
* **River blue UI and a logo on the idle screen.** All colours live in one palette asset, and the idle image went from 8 MB to 27 KB.
* **A "Details" button when a video fails.** It shows what went wrong and where to ask for help.

**Playback stays together:**

* Positions follow VRChat's server clock.
* The video no longer jumps back to the start when the owner leaves.
* Drift is corrected only when you are nearly a second off.
* ReSync now fixes only your own stuck screen.

**Also:**

* VHub tracks play on AVPro, so YouTube is no longer stuck at 360p.
* With its default off, the AudioLink module no longer stops AudioLink for everyone who joins.
* The playlist tabs lift again when pointed at. Welcome back.

Anything odd? Tell us on our [Discord server](https://discord.gg/tkrHek6PvN).
