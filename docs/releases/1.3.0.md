**KawaPlayer 1.3.0** — YYYY-MM-DD

今回の目玉は、**持ち運べる KawaPlayer タブレット**です。

これまで、ワールドに置いた KawaPlayer を操作するには、スクリーンの前まで歩いていく必要がありました。1.3.0 では、手に持てるタブレットから、どこにいても操作できます。プレイリストも URL の入力も、手元でどうぞ。画像をみんなに見せたり、誰が来ているかを確かめたり、自分だけの見え方を変えたりもできます。

あわせて、見た目を KawaPlayer らしい「川の青」にしました。動画が再生できないときの手助けも増えています。変わったところを紹介します！

## タブレットを持ち歩けます

* **`GameObject > KawaPlayer > Tablet` から置いて、インスペクターで使う KawaPlayer を選ぶだけ。** 何台置いても大丈夫です。
* **KawaPlayer アプリ:** ワールドの KawaPlayer の画面がそのまま入っていて、再生・一時停止・シーク・音量・URL 入力・プレイリストを手元で操作できます。
* **画像アプリ:** URL を入れると画像を画面いっぱいに表示し、タブレットを見ている全員に同じ画像が映ります。表示した画像は最大 5 枚まで一覧に並ぶので、あとから選び直せます。
* **見せたい画像は、「KawaPlayer に送る」でワールドのスクリーンに映せます。** 何かを再生中でも、確認なしですぐに切り替わります。
* **画像が出ないときは、その理由と、次にすることが出ます。** VRChat の設定で許可が必要なサイトなのか、サイトが VRChat からの読み込みを断っているのかなどを見分けて案内します。許可をオンにしたあとなどは、「もう一度読み込む」で読み直せます。
* **訪問者アプリ:** 今いる人と前にいた人の一覧、入退室のログ、アバターの顔写真を見られます。顔写真は、ワールド制作者がオフにできます。
* **設定アプリ:** 明るさ・左右反転・最大解像度・遅延補正・AudioLink・言語など、自分だけに効く設定を変えられます。インスタンスオーナーなら、自動再生の URL もここで決められます。
* **バージョン情報:** KawaPlayer の版と更新履歴が見られます。
* **タブレットを縦に持つと、画面も縦になります。** どのアプリも縦向きの配置に切り替わり、設定の分類は上のタブに並びます。逆さに持てば、画面も逆さに回ります。KawaPlayer アプリは、ボタンと文字を小さくしないよう横向きのままです（逆さに持ったときは回ります）。
* **開いているアプリは、見ている全員に同期します。** あとから入ってきた人にも、同じ画面が映ります。
* **画面の下のホームボタンは、白い □ が目印です。** アプリを開いているあいだは周りが LED のように青く光り、押すとホーム画面に戻ります。
* **タブレットの裏には、銀の KawaPlayer のロゴが入っています。** 光の当たり方で、金属のように浮き上がって見えます。
* **VR では、触れたところのまま持てます。** 置き忘れたタブレットは、戻すボタンや、しばらく放っておくことで元の場所に戻せます（ワールド制作者の設定で使えます）。

## KawaPlayer の色になりました

* **UI の色を、YamaPlayer のピンクから KawaPlayer 独自の「川の青」に変えました。** タブレットも同じ色です。
* **スクリーンの右の列のタブ（キュー・履歴・プレイリスト）を指すと、文字が少し上がります。** YamaPlayer にあった動きが効かなくなっていたのを、元に戻しました。タブレットの KawaPlayer アプリと、操作パネル（Playlist Panel）のタブも同じです。
* **何も再生していないときは、スクリーンに KawaPlayer のロゴが出ます。** これまでは真っ黒でした。ワールド制作者は、インスペクターの「待ち受け画像」で差し替えられます。
* **ワールド制作者は、色を 1 か所で変えられます。** 配色アセット（`KawaPlayerPalette`）を編集すれば、すべての UI に反映されます。YamaPlayer の配色も選べます。

## VHub の曲が高画質に

* **VHub のプレイリストの曲を、AVPro で再生するようにしました。** これまでは Unity Video Player で再生され、YouTube の曲が 360p になっていました。
* **KawaPlayer は、いつも AVPro から始まります。** ワールドに入った直後も、設定画面の表示も AVPro です。
* **ワールド制作者向け:** プレイリストエディターに取り込み済みの VHub のプレイリストも、ワールドをビルドし直すだけで AVPro になります。Unity で再生したい曲は、VHub から取り込んでいないプレイリストに入れてください。

## 再生できないときの手助け

* **エラーの下に「詳細」ボタンが出ます。** 押すと、直近のエラーの内容と、問い合わせ先の案内が出ます。その画面のスクリーンショットを送ってもらえれば、原因を探しやすくなります。
* **問い合わせ先の Discord の URL は、コピーできる欄に入っています。** VRChat ではワールドからリンクを開けないので、欄から写してブラウザに貼ってください。
* **ワールドの中で選べる動画プレイヤーを、AVPro にまとめました。** Unity Video Player は、AVPro で再生できないときの切り替え先として、これまでどおり使われます。
* **画像を映したあとに入れた動画の URL が、画像として読み込まれて失敗しなくなりました。** 次の URL は AVPro で再生されます。続けて画像を映したいときは、設定で「画像」を選んでください。
* **「Access Denied」で再生できないときは、「Allow Untrusted URLs」をオンにするよう案内し、それでも流れなければワールドの制作者に連絡するよう伝えます。** 制作者が何を直せばよいかは「詳細」の画面に出るので、その画面を撮って見せてください。
* **VHub のページのアドレスや「シェア」の URL を入れたときは、「VRChat用URLをコピー」で写した URL を入れるよう案内します。** ページの URL では、プレイリストを読み込めないためです。

## みんなの再生がそろいます

* **一部の人だけ、再生の位置がずっとずれたままになることがある問題を直しました。** 位置を合わせる時計を、VRChat のサーバーの時刻に替えました。これまでは、VRChat と時計を合わせられなかった人が、その時計のずれの分だけずれて再生していました。
* **インスタンスのオーナーが抜けたときに、全員の動画が先頭に戻ってしまうことがある問題を直しました。** 再生中にエラーから読み込み直したときも、先頭に戻らず、それまでの位置から続きます。
* **ずれの合わせ直しで、映像が何度も引っかからないようにしました。** 合わせ直すのは 1 秒近くずれたときだけにし、読み込みが追いつかずに止まっているあいだは待ちます。これまでは、小さなずれでも合わせ直して読み込んだ分を捨て、また止まることがありました。あとから準備ができた人が、少し遅れたままになることもなくなりました。
* **自分の画面だけ止まったときは、「ReSync」（画面の左の列の、読み込み直しのボタン）で戻せるようになりました。** エラーで止まった画面や、読み込み中のまま進まない画面も読み込み直し、ほかの人と同じ位置から続きます。読み込み直すのは押した人の画面だけで、ほかの人には何も届きません。
* **「ReSync」は、押して何かが起きるときだけ押せます。** 全員が止まっているときと、読み込み中のしばらくのあいだは押せず、アイコンが薄くなります。
* **権限の管理（PermissionManagement）を入れたワールドでも、「ReSync」は誰でも押せます。** 押した人の画面だけのもので、ほかの人には何も起きないためです。
* **ワールド制作者向け: ライブ配信のイベントのための「全員リロードボタン」を置けるようになりました。** モジュール管理で「全員リロードボタン」のモジュールを足してから、`GameObject > KawaPlayer > Global Reload Button` でボタンを置きます。押すとインスタンスの全員がそれぞれの画面で読み込み直し、配信の遅れがそろいます。ふつうの動画では、最初からではなく今の再生位置から続きます。権限の管理を入れたワールドでは、Editor 以上の人だけが押せます。スクリーンやタブレットには出ないので、要るワールドにだけ置いてください。

## 「デフォルト URL」は「自動再生」になりました

* **インスタンスオーナーが入室時に流す動画を決める機能の名前を、「デフォルト URL」から「自動再生」に変えました。** 中身はそのままで、保存した URL もそのまま使われます。
* **設定画面の欄の見出しは「自動再生(Global)」です。** 再生速度などの欄と同じく、(Global) は、決めた URL がインスタンスの全員に効く印です。
* **ワールド制作者向け:** モジュール管理では「自動再生(Owner)」と表示されます。YamaPlayer から引き継いだ AutoPlay は「自動再生(World)」です。(Owner) はインスタンスオーナーが VRChat の中で、(World) はワールド制作者が Unity で、流すものを決めます。
* **2 つの自動再生を両方とも有効にすると、モジュール管理とビルドのログにエラーが出ます。** どちらが流れるかが入室のタイミングで決まってしまうので、どちらか一方を使ってください。ビルドは止まりません。

## ワールド制作者向けの細かいところ

* **モジュール管理と KawaPlayer のインスペクターの一覧に、外部プレイリスト読込（PlaylistLoader）と自動再生(Owner) が出るようになりました。** 名前のない行や、出てこないモジュールはもうありません。
* **一覧の「無効化」は、モジュールの部品ごと切り替えます。** ビルドでも、部品ごと除かれます。
* **KawaPlayer に最初から入っているモジュールは、一覧から削除できなくなりました。** 消すと追加し直せないためです。使わないときは無効化してください。
* **権限の管理（PermissionManagement）が、タブレットにも効くようになりました。** 再生の権限がない人は、タブレットから KawaPlayer に画像を送れません。
* **同じモジュールを 2 つ置いたときのエラーが、KawaPlayer のインスペクターにも出ます。**
* **KawaPlayer のインスペクターから「プレイヤー」欄をなくしました。** プレイヤーはいつも AVPro から始まり、ビルドのときに並びがそろえられます。
* **自動再生(World) の既定のプレイヤーを AVPro にしました。** 既定のまま置いてあった自動再生も、AVPro で再生します。
* **使っていなかった画像 9 枚を、パッケージから消しました。** 自分の UI で KawaPlayer の `Assets/Images` の画像を使っている場合は、参照が外れていないか確かめてください。
* **KawaPlayer のロゴと、クイックスタートガイドのポスターを、素材として入れました。** パッケージの `Media~` フォルダー（Unity には出ないので、エクスプローラーで開いてください）にあり、KawaPlayer を置いたワールドへの掲示や紹介に使えます。販売するワールドへの同梱もできます。使える範囲は `Media~/LICENSE.md` を見てください。
* **KawaPlayer のインスペクターに「使い方を見る」ボタンを置きました。** 押すと、GitHub にある使い方ガイドが開きます。
* **パッケージから、文書（`docs`）・開発用のファイル・テスト・ポスターの元（`Media~/poster/source`）を外しました。** プロジェクトに入る KawaPlayer が小さくなります。使い方ガイドとポスターの元は GitHub にあります。
* **動画が Access Denied で流れないとき、「詳細」の画面に、VRChat.com の Video Player Allowed Domains に足すドメインが出ます。** Public と Group Public のインスタンスでは、そこに載っていない信頼されていないサイトの動画は流れません。
* **AudioLink のモジュールで「デフォルトでAudioLinkを有効にする」がオフのとき、入った人の AudioLink を止めてしまう問題を直しました。** KawaPlayer 以外の音（DJ ブースなど）で AudioLink を使っているワールドでも、そのまま動きます。

## 自分のスクリプトから KawaPlayer を呼んでいる場合

* **古い名前のまま残していた API を消しました。** 自分の U# スクリプトから呼んでいるときは、下の表の新しい名前に書き換えてください。

| 消した API | 代わり |
| --- | --- |
| `Controller.VideoPlayerHandle` | `Controller.Handler` |
| `Controller.MirrorInverse` | `Controller.MirrorFlip` |
| `Controller.Emission` | `Controller.Brightness` |
| `UIController.AddUrlTopToQueueEvent` | `UIController.AddUrlToQueueEvent` |
| `UIController.PlayUrlTopEvent` | `UIController.PlayUrlEvent` |
| `PlaylistLoader.LoadPlaylistFromUrlWithFeedback(url, ui)` | `PlaylistLoader.LoadPlaylistFromUrlWithFeedback(url, ui, null, string.Empty)` |
| `PlaylistLoader.LoadResultQueueUnavailable` | `PlaylistLoader.LoadResultNoSlot`（値は 7 のまま） |
| `Modal.Show(...)` | `Modal.TryShow(...)` |

* **`Modal.TryShow` は、ほかの質問が出ているあいだは何も出さずに `false` を返します。** これまでの `Show` のように、断ったことを閉じるイベントで知らせることはしません。
* **`UIController.ShowMessage` は、表示できたかを `bool` で返すようになりました。** 戻り値を使わない呼び方は、そのまま動きます。
* **`AddUrlToQueueEvent` と `PlayUrlEvent` は、URL の確認ダイアログへの答えです。** ダイアログが出ていないときに外から送っても、何も起きません。
* **呼ばれることのなかった `YamaPlayerListener.AfterVideoReloaded` と `PermissionManagementUI.BeforeUserPlayVideo`、何もしない `AutoAssign` 属性を消しました。** 上書きや指定をしていた場合は、その部分を消してください。

## 困ったら

「こんなことが起きた！」があれば、気軽に [Discord サーバー](https://discord.gg/tkrHek6PvN) で教えてください。動画が再生できないときは、画面の「詳細」ボタンの内容も添えてもらえると助かります。あなたの報告が次のリリースを作ります。

## 入手方法

**1.3.0 には、VRChat Worlds SDK 3.10.2 以上が必要です。** プロジェクトの SDK がそれより古いときは、先に VCC の **Manage Project** で VRChat SDK（Worlds と Base）を新しくしてから、KawaPlayer を更新してください。

**1.3.0 に更新したワールドは、PC と Quest の両方を 1.3.0 でビルドし直して公開してください。** 再生の同期のしくみが変わったので、PC と Quest で KawaPlayer の版が違うと、同じインスタンスに一緒に入れなくなります。更新の前から開いているインスタンスにも入れないことがあるので、確かめるときは新しいインスタンスを立ててください。

VCC（VRChat Creator Companion）から入れます。KawaPlayer のリポジトリを追加済みなら、1.3.0 はもう更新候補に出ています。まだの人は、下の URL をブラウザのアドレスバーに貼って Enter を押すと VCC が開き、リポジトリが追加されます。あとは **Manage Project** からプロジェクトに **Add** するだけ。

```
vcc://vpm/addRepo?url=https://mega-gorilla.github.io/vpm-repos/index.json
```

VCC が開かない場合は、**Settings > Packages > Add Repository** に `https://mega-gorilla.github.io/vpm-repos/index.json` を入力してください。更新したら、ワールドをビルドし直してアップロードすると反映されます。タブレットは `GameObject > KawaPlayer > Tablet`、全員リロードボタンは、モジュールを足してから `GameObject > KawaPlayer > Global Reload Button` で追加できます。

*English:* The big one: a **KawaPlayer tablet** you can carry around. Place it from `GameObject > KawaPlayer > Tablet`, point it at your KawaPlayer, and control the player from your hand — playback, URLs and playlists — plus apps to show an image to everyone (the last five stay in a list to pick again, and "Send to KawaPlayer" puts it on the big screen at once), see who is here and who has been, and change settings that only affect you; hold the tablet upright and the screen turns with it, with a portrait layout for every app but the KawaPlayer one; the home button below the screen glows while an app is open, and a silver KawaPlayer logo sits on the back; when a picture will not load, the image app says why and what to do, with a "Try again" button. The UI is now KawaPlayer's own river blue, with every colour kept in one palette asset, and an idle screen shows the KawaPlayer logo. When a video will not play, a "Details" button shows what went wrong and where to ask for help, with the Discord address in a field you can copy. After a picture, the next URL plays as a video again unless you chose Image Viewer in the settings. VHub playlist tracks now play on AVPro instead of Unity Video Player, so YouTube is no longer stuck at 360p; rebuild your world to apply it to playlists you imported earlier. "Default URL" is now called "Autoplay" (listed as Autoplay (Owner) in Module Manager, beside AutoPlay's Autoplay (World)); saved URLs carry over. The package now carries KawaPlayer's logo and a quick start poster in its `Media~` folder, which you may put up in your world or use to introduce KawaPlayer (see `Media~/LICENSE.md`). The Access Denied message now asks you to turn on "Allow Untrusted URLs" and, if the video still will not play, to contact the world's creator, who finds in the Details screen the domain to add to Video Player Allowed Domains, and pasting a VHub page or share URL tells you to use the VRChat URL instead. The autoplay card is titled Autoplay (Global), like the other settings that reach everyone. For creators: the inspector has a button that opens the user guide on GitHub, the package no longer carries the docs, development files, tests and the poster's source, and the AudioLink module no longer stops AudioLink for everyone who joins when its default is off. Playback is now placed by VRChat's server clock, so a player whose clock VRChat could not sync no longer plays off from everyone else, and the video no longer jumps back to the start for everyone when the instance owner leaves or a player recovers from an error. Drift is now corrected only when a player is nearly a second off, and never while the video is still buffering, so it no longer stutters from seeking over and over. ReSync now brings back your own screen when it stopped on an error or got stuck loading, touching no one else's, and can be pressed only when it would do something, whatever your permission level. For live events, creators can add the Global Reload Button module in Module Manager and place a Global Reload Button (`GameObject > KawaPlayer > Global Reload Button`) that has everyone reload their own screen at once, resuming where everyone is; with PermissionManagement, only Editors and above can press it. If your own scripts call KawaPlayer, the old names kept only for compatibility are gone (`VideoPlayerHandle`, `MirrorInverse`, `Emission`, `AddUrlTopToQueueEvent`, `PlayUrlTopEvent`, the two-argument `LoadPlaylistFromUrlWithFeedback`, `LoadResultQueueUnavailable`, now `LoadResultNoSlot`, and `Modal.Show`, now `TryShow`); the table above has their replacements. Rebuild and publish both your PC and Quest builds with 1.3.0, since builds of different versions cannot share an instance, and test in a new instance. KawaPlayer 1.3.0 needs VRChat Worlds SDK 3.10.2 or later: if your project's SDK is older, update the SDK (Worlds and Base) in VCC first. Anything odd? Tell us on our [Discord server](https://discord.gg/tkrHek6PvN).
